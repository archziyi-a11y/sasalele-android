# 客户画像与 AFTB 线索分级纠偏报告

交接日期：2026-11-05（Asia/Shanghai，客户端日期）。接收人：旧飞书画像、新销售助手画像及 AFTB 相关功能负责人。本文交接已复现的问题、待查范围和验收要求。调查依据为本地源码、历史审计、用户确认的业务分工及一次离线函数复现。

## 一、请先处理的偏差

业务要求由模型结合上下文区分沟通场景。销售助手虽然调用了模型，最终交付的阶段和标签仍由旧关键词函数决定。请首先查清这些字段的所有消费者，消除关键词对业务结论的裁决权，再用同一案例从模型输入追到最终字段。只改提示词或增加否定词无法修复字段组装路径。

市场部根据沟通事实按现行口径分级。家长关联多个孩子本身不妨碍分级。更新已有行时需要定位目标记录，新建行另按现行建行条件处理。线索实际来源由品宣看表后核实。不得把来源核实或孩子拆分作为市场分级的通用前置条件。到访事实、画像业务阶段、市场等级是三个不同字段；具体等级以业务现行规则为准。

## 二、一个已复现的错误

入口为 marketing-chat-insight 的 profile_aggregate.infer_stage_and_tags。分别提交仅含一条 inbound 文本的快照，投诉关键词配置为空：

| 输入（合成） | 实际阶段 / 标签 | 关于到访可以确认的事实 |
|---|---|---|
| 我昨天到店了 | 到店 / 试听、到店 | 客户自述到访；未提试听 |
| 我昨天没有到店 | 到店 / 试听、到店 | 否认昨天到访 |
| 如果到店需要预约吗 | 到店 / 试听、到店 | 咨询流程，到访尚未得到确认 |

三例均来自真实函数执行，不涉及模型或正式表。它们证实阶段函数混淆肯定、否定和条件问句。是否已有正式记录因此错级、是否影响绩效，仍无观测证据。

## 四、验收顺序与交付证据

1. **追踪字段。** 列出阶段、标签及市场等级从输入、提示词、模型返回、组装、缓存到响应和消费者的路径。用上面三句及一条前后纠正的合成对话追踪，标明每步输出。离线替身应专门构造“模型正确、旧规则相反”的结果，以检出模型之后的覆盖。验证否定和假设不会成为“已到访”，未提试听不会成为“已试听”。不预设三人必须分成三个市场等级。
2. **核对输入与状态。** 加入“员工问已报名吗”“最后一句取消预约”“新信息只有未识别的非文本消息”等案例。核对消息方向、裁剪边界、证据对具体值的支持、缓存来源和覆盖时间。判定为未知时保留未知。用模型失败、空摘要和缓存复用核对实际产出统计；改变回执措辞后，操作状态应保持一致。
3. **再做真实质量对照。** 在获准范围内，以同一工作号、同一客户、同一信息截止时间配对旧画像和新画像。先用市场现行口径、原消息及人工复核形成参考判断，再分别用两份画像走同一 AFTB 隔离评测。区分“真实历史存量质量”与“同输入下生成能力”；旧快照或可比输入缺失时列为不可配对。报告目标分母、可配对数、缺摘要数、正确补出、遗漏、无依据字段、错级方向，并分别评价补空、更新、新建。来源核实归品宣。没有正式使用日志时，绩效影响保持待核实。
4. **按影响交付。** 先报告离线复现与相关回归，再按项目门禁冻结版本，区分真实模型、隔离表和生产观测。提交修改文件、关键反例的修前/修后结果、未覆盖项、缓存与历史记录处理、实际部署状态。模型/隔离环境按既有授权执行，不能从本报告推导出生产写表、切换路由或批量重算授权。
