## 总体结论

两份报告共同支持：功能入口、面板容器、信息层级和反馈方式需要重新组织，单纯换皮不能解决问题。对方报告对容器遮挡、深色主题和设置分区的补充有价值。

但“不敢用”“每写一条回复来回两趟”属于尚未经过用户任务观察的判断，不能当作测量结果。四维分数是主观评估，不宜作为改版成效的量化基线。“拆模态是唯一真正影响使用的问题”也过强：草稿保留、失败与空列表混淆、客户确认方式同样影响完成任务。

## 对照结果

| 主题 | 核查结论 | 处理建议 |
| --- | --- | --- |
| 面板统一占据大部分屏幕 | 源码确有统一约 90% 高度容器；遮挡聊天成立。各任务需要多少可见聊天尚未验证 | 优先做可展开的紧凑容器原型，分别验证阅读、输入、选物料；不统一套固定比例 |
| 六个入口平权、缺少标签 | 入口可辨识性问题成立；“帮我回最高频、设置一年两次”无使用数据支持 | 用明确中文标签与主次层级改进；先核对跟进、物料、回复的日常任务，再决定是否收进更多 |
| 空、加载、失败、未配置状态 | 共识成立。独立观察还发现团队物料请求失败时同时显示暂无物料 | 将未加载、加载、失败、真实空库、搜索无结果、缺少工作号分别表达；允许保留缓存 |
| 重复标题 | 源码和观察支持；部分外层标题落为销售助手，内层继续重复 | 每个面板一个主要标题，保留必要分组，不只补枚举后继续堆标题 |
| 深色模式硬编码 | 源码存在白底、固定浅灰图标底与描边 | 统一语义颜色，并实际检查深浅主题；是否保留边框由层级效果决定，不机械全部改阴影 |
| 设置暴露管理信息 | 业务服务、诊断、发机配置与日常开关混排；源码存在 Y 轴数字滑杆 | 日常设置在前、工作号清晰可达、管理诊断折叠。不要用秘密长按代替可发现入口 |
| 物料动作过多 | 上传、删除、复制、分享缺少层级，建议成立 | 主要使用动作突出，管理动作进入更多；保留点击标题编辑和图片放大等已验收能力 |
| 生成结果不突出、输入切换风险 | 独立评审补充，对方阻断态无法覆盖 | 结果优先展示；验证关闭、切换、键盘和返回后的输入与结果保留，再定容器交互 |
| 机器标识与业务确认 | 独立评审发现存在要求销售核对长 ID 的文案 | 向销售展示工作号、备注、头像等可辨识信息，内部继续校验准确对象 |

## 不直接采纳的细节及原因

1. **固定 62% 宽侧栏、固定半屏输入面板。** 这是方案假设。窄手机剩余聊天区域可能不足以阅读；半屏叠加键盘后可能挤掉结果。须用典型工作机、小屏大字体、键盘开启状态验证，并检查窗口触摸与返回行为。
2. **删除按钮一碰就误删。** 当前 `FloatingWindowContent.kt:1051` 只设置待删除对象，约 987–989 行另有确认删除步骤。动作层级可以改善，但不能把已有确认当作缺失。
3. **9sp 约为 9px。** 单位混淆，420dpi 下二者并不等同。9sp 作为关键客户名确实偏小，但具体字号与摆放应由可读性验证决定。
4. **44dp 关闭触控区。** 本项目是原生 Android，采用至少 48dp 的触控目标；可用较小视觉图标，不缩小实际可点区域。
5. **无字号阶梯。** 当前已有 titleLarge、titleMedium、headlineSmall 等样式调用，不能说完全没有；问题是跨面板的层级规则和密度未统一。
6. **必须关闭动态取色并使用红色。** 动态取色是主题选择，不天然是缺陷。品牌资产的存在也不自动等于产品主色规范。先比较一致的品牌方案与现有主题，不把主动作和错误状态混为同一种语义。
7. **淡色星星必然违反图标对比标准。** 是否属于真正禁用控件影响标准适用；当前点击还会给出识别客户提示。低可辨识性值得修，但不把笼统阈值当作已确认违规结论。
8. **加载只能用骨架屏。** 有稳定列表结构时适合骨架；生成任务需要阶段反馈和等待状态。按任务选择，不排斥进度指示。
9. **最近两句／三条消息语境条。** 只能展示实际取得且归属当前客户的上下文，不能因为原型写了这一句就假设接口具备该数据。
10. **采集原稿与最终稿作为训练数据。** 这不是本轮 UI 改版所必需的能力，不随评审一起引入采集或存储变更。
11. **一天即可完成入口改造。** 尚未拆解状态、导航和验证成本，不承诺此工期。

对方原型采用成人转行课程的对话，与本产品高考美术培训场景不同。后续原型应用合成的家长咨询、学生情况、物料查找与跟进案例，以便评价真实业务中的信息密度。

## 建议执行顺序

### 第一批：先稳定操作与反馈

- 确定草稿、生成结果、搜索条件和滚动位置在关闭／切换／返回时的保留规则，并核对发布版表现。
- 分离加载失败和真实空列表；统一当前工作号、当前客户的业务化展示。
- 合并重复标题；设置分区；保留既有点击标题编辑、图片预览、个人别名和团队标题边界。

### 第二批：验证整体布局

- 用“选客户→画像→指导／回复”“找物料→预览→复制／分享”“跟进列表→复制姓名→返回微信”三条真实任务画交互原型。
- 比较紧凑面板与展开面板；回复编辑时保留必要上下文，键盘出现后仍可操作。
- 决定工具条的标签、主次和更多入口。跟进是否折叠由任务需要决定，不沿用无依据的频次排名。

### 第三批：统一视觉并验收

- 使用统一字号、间距、按钮级别、颜色和深浅主题，视觉方向阶段再结合 Taste Skill。
- 用同一组任务检查小屏、大字体、键盘、关闭后再打开、加载失败、已有结果再编辑等状态。
- 分别记录源码实现、模拟器验证、真实工作机验证；未验证项明确保留，不用总分替代结果。

本次只完成意见核对与优先级整理，未修改 APP、安装新版本或进行生产业务操作。
