# 方舟直接资料读取试验

2026-10-12。只读方舟，未触发自动画像任务、未调用LLM、未写飞书或方舟。两位客户取自既有授权身份样本，不扩大到全量聊天。

## 实际结果

两个详情请求都通过响应工作账号ID和客户ID双标识校验。请求耗时分别1520.3ms、403.7ms（宿主perf_counter，从详情调用开始至解析验证后）；样本过少，不作为平均速度或长期指标。

响应有nickname、avatar、labels、conRemark、desc等原生资料字段；昵称非空，备注为空；未出现完整画像摘要字段。不能据此证明所有方舟接口均无画像，只能说明当前已验证详情路径没有销售画像摘要。

旧profile_enrich处理本地聊天快照并推断阶段/标签，对部分客户调用LLM生成摘要，再写飞书画像表。因此“直接方舟资料”与“聊天派生画像”是两层来源，不能互相冒充。

## 可复用实现

tools/fetch_fangzhou_identity.py提供单客户详情读取、双标识校验、5分钟身份观察缓存及refresh刷新。身份原文只在Git忽略private/fangzhou-identity-cache保存，控制台只输出状态和性能元数据。缓存返回保留原观察时间，不将缓存命中当新拉取。

实际冷读取1次请求2270.5ms，随后缓存命中0次请求6.1ms。两次均为同一测试客户，不能作为真实生产延迟承诺。

没有把后端凭据或缓存打入APK，也尚未接安卓业务查询服务。

## 效率路线与范围

- 识别匹配后的客户直接按双标识读详情，缓存命中不再次扫描13/14工作号。
- 名称发现仍需要可搜索的客户索引。首次构建可用分页好友列表；该接口增量游标/跨账号服务端搜索能力未在本轮验证，不声称已经完成全量索引。
- 身份、近期聊天、派生摘要分开缓存；单客户需要最新局面时按需拉该会话，不执行profile_enrich(refetch=True)的全账号按日发现。
- 消息规范化、方向、时间和摘要提示词可复用mktci现有路径。消息派生画像需明确数据窗口、生成时间、来源及缺失，不能把旧表最后enrich当最新摘要时间。
