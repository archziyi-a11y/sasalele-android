# SASALELE UI 与交互优化报告

日期：2026-10-16（Asia/Shanghai）。本轮由开发代理操作 Windows 开发机与 Android 模拟器，不使用真实微信账号，不读取真实客户聊天，不部署服务器。

## 范围与审查结论

已完整阅读 UI-EXPERIENCE-HANDOFF-20261016.md，随后核对适用 AGENTS.md、Android 技能、指定源码与五份业务记录。Android 仓库及其父目录未找到额外 AGENTS.md。保留两个仓库的既有修改；本报告不是整仓历史变更的归因清单。

本轮优化现有工作手机流程：首页准备、客户识别与人工确认、画像阅读、帮我回/润色、面板可用性。没有修改业务接口、业务提示词、模型、生成触发方式、账号访问范围或服务器部署，也没有新增群聊支持、销售登录、自动发送或电脑配对。

源码确认的主要问题：

- MainActivity 首页仍是模拟私聊/群聊列表，与正式工作手机用途冲突。
- FloatingWindowContent 的实际业务面板固定 280×400dp，工具条与面板并排挤占宽度；必须检查真实调用链，不能只改维护用 RealRecognitionPanel。
- 候选列表和资料页直接展示长双标识、技术来源和多个时间字段，主任务不突出。
- 生成结果不可编辑，未展示服务端 warnings；润色说明与帮我回混用聊天读取表述。
- 画像已有结构化 facts/inferences/unknowns，但 Android 只展示摘要。

## 实施结果

- 首页替换为权限准备、开启助手、使用步骤和工作机服务检查。返回系统设置后刷新悬浮权限状态；未授权时禁用开启助手。移除生产首页的模拟聊天列表。
- 悬浮面板使用可用宽度（最大 480dp）和可用高度的 90%，处理系统栏与输入法 inset；打开面板时隐藏工具条，避免并排遮挡。新增显式关闭，关闭后恢复工具条；打开面板时不沿用工具条拖动偏移。
- 候选列表优先姓名、工作号名称、标识尾号；人工确认页保留完整工作号 ID 与客户 ID，提示必须人工核对，并提供返回候选。查询范围和记录时间折叠；未匹配不再暗示客户不存在。
- 资料页分层呈现摘要、记录中明确表达的信息、待核对推断与理由、未知项、记录覆盖范围。技术来源映射为可读名称，身份及时间移至详情。仍说明模型摘要需要人工核对；没有结构化字段时不假装提取完成。
- 帮我回与润色分别说明输入和依据；润色仍必须填写原文，补充局面可选。结果支持编辑，显示服务端调整说明，复制实际编辑文本。保留生成进度、停止等待及服务端任务可能继续的提示。
- 没有把“安装”“设备配置已保存”“服务可用”写成“微信工作号已绑定方舟”或“业务验收通过”。

设备通过当次 adb devices -l 重新确认：emulator-5554 在线，Android API 36；另一个 emulator-5556 离线，未用于测试。模拟器截图状态栏使用设备自身时钟，不能与报告的 Asia/Shanghai 时间混作耗时指标。本轮不报告性能 SLA、入库延迟或跨设备时间差。

首轮启动出现系统记录的启动 ANR；停止本轮 Gradle 守护进程释放内存后重跑。首次执行由代理终止，日志中的 Process crashed 不作为功能测试通过；保留原记录。

正常配置回归：18 项执行，17 项通过、1 项失败。新增 4 项 UI 测试通过：准备首页、候选必须人工确认、结构画像分层、润色调整说明及编辑复制。业务规则、截图授权失败恢复、黑帧门控等通过。失败为真实中文 OCR 合成图精确文本断言：“清美”被识别为“请姜”；没有修改断言掩盖失败，也没有为其硬编码纠正。身份搜索仍需允许人工修正，不能认定 OCR 名称可靠。

小屏布局：720×1280px、320dpi（360×640dp）、系统字体 1.3，4 项 UI 测试全部通过，包括实际剪贴板文本断言。手动检查服务创建的实际悬浮窗口：打开资料面板后工具条隐藏；点击关闭恢复工具条；再次进入搜索后输入框可获得焦点，关闭按钮可见。没有在该实际面板输入姓名或发起真实查询。

最终代码收尾后再次安装同源 debug 包复测：正常配置 4/4 通过，小屏字体 130% 配置 4/4 通过。证据为 `tests-final-normal.log`、`tests-final-small-font130.log` 与 `final-normal/`、`final-small-font130/` 截图。它们是相同 4 项用例的配置复测，不能累加声称新增 8 项独立业务覆盖。最后一次只是候选区间距调整及测试截图定位；没有以复测覆盖掉前述 OCR 失败。

模拟器使用浮动中文键盘，会覆盖左侧部分文字。应用的滚动与系统栏适配不等于可以控制系统浮动键盘位置；本轮未证明所有键盘遮挡已消除。组件测试截图与实际悬浮窗口截图分别留存，不能互相替代。

## 未验证与使用边界

- 当前没有微信工作号已绑定方舟、可用于完整验收的工作机。本轮没有完成真机微信截图 → OCR → 真实客户 → 双标识确认 → 画像/生成 → 人工复制的完整业务验收。
- 未验证 OPPO/OnePlus 截图保护、厂商悬浮权限、系统后台回收、真实键盘、旋转及全部屏幕/字体组合。模拟器不能替代这些检查，也没有规避系统截图保护。
- 合成接口验证只证明 UI 状态和交互，不证明生产 HTTPS 鉴权、方舟数据覆盖、模型语义质量或现行价格/优惠资料完整。
- OCR 精确识别失败仍是已知限制。人工核对双标识和姓名修正不可省略。
- 旧销售指导、素材、提醒与维护入口保持既有边界，没有扩展其业务能力；不宣称这些历史功能已全部重新验收。

后续具备授权工作机时，必须先明确手机、微信工作账号、已绑定方舟关系及观测记录条件，再安排单次有限客户操作；不让用户重复盲测，也不扩大读取无关聊天。
