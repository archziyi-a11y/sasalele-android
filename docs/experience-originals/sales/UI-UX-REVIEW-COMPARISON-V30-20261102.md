# SASALELE v30 UI/UX 整改建议

更新：2026-11-02，北京时间。当前阶段：改版方向与实施建议。

## 改版判断

**采用另一份设计评审的主要方向：重做悬浮面板的交互形态，建立清晰的入口层级，精简销售眼前的信息，再统一视觉。**

SASALELE 的工作现场是微信聊天。销售打开助手，是为了查看客户、找物料、组织回复，然后继续聊天。当前各功能共用接近整屏的面板，一打开就遮住工作现场；入口缺少文字解释，面板内标题、说明、操作按钮又争夺注意力。这些问题已经足以支持结构改版。

新版本应让销售看得懂入口，拿得到内容，轻松返回聊天；需要深入阅读或编辑时，再展开工作区域。

两份评审的价值在这里汇合：对方指出了容器与入口的结构问题，独立评审补充了草稿保留、结果展示、失败反馈和客户确认的问题。这些一起纳入改版。

## 一、先改面板：让助手融入聊天过程

按任务采用不同容器，替换统一 90% 高度的外壳。

| 任务 | 第一版原型方案 | 关键操作 |
| --- | --- | --- |
| 帮我回、润色 | 底部半屏起步，可向上展开 | 顶部显示当前客户与本次使用的对话上下文；结果在主要区域，可编辑并复制 |
| 客户资料、销售指导 | 紧凑侧面板，可展开长内容 | 默认显示关键资料或指导结论，细节逐层展开；收起后继续聊天 |
| 销售物料 | 侧面板用于搜索和取用，图片可独立放大 | 搜索、筛选、预览、复制／分享连续完成；新增和编辑进入专门区域 |
| 跟进提醒 | 较大列表面板 | 快速浏览联系人、复制姓名和处理提醒，关闭后回到微信 |
| 设置 | 完整设置面板 | 日常开关、工作号、管理工具分组展示 |

侧栏先以报告提出的约 62% 宽度做原型，回复面板以半屏做起点。在典型工作机上根据聊天可读范围、内容长度和键盘占用调整尺寸。尺寸调整是原型迭代的一部分。

紧凑面板保留聊天可见区域，侧栏外的聊天可继续操作；展开状态集中处理长内容。键盘出现时，让输入框、生成结果和主要操作保持可达。面板顶部使用统一关闭图标，返回键按“键盘→子页面／弹层→面板”的顺序退出。

**内容保留随容器一起实现：**同一客户下收起或切换面板后，恢复输入、已生成内容和编辑稿；修改补充问题时保留旧结果并提示可重新生成。切换客户后按客户分别管理内容，避免把上一位客户的草稿带入新会话。

## 二、整理入口：让销售一眼知道点哪里

采用“少量明确入口＋更多”的结构，为主要入口加中文短标签。

第一版原型建议保留 **回复、物料、跟进** 三个直接入口；当前客户以头像和名称单独呈现，点击进入资料，销售指导在客户区域提供明确入口；设置等低频操作进入“更多”。这样既缩短工具条，又保留我们已经投入实际使用的跟进路径。

回复作为明确的主操作给予视觉强调，其他入口保持统一且清晰。展开工具条后标签可读，收起时占用小。当前客户名称移出 48dp 图标内部，解决关键身份信息挤成小字的问题。

这一版作为可点击原型落实，直接走回复、物料和跟进三条任务检查顺畅程度，再调整入口位置。

## 三、精简面板内容：优先呈现任务与结果

### 回复与销售指导

- 顶部只保留功能名称、当前客户和必要的上下文。
- 有结果时，结果成为页面主体；补充问题和参数退到次级区域，仍可随时修改。
- 回复的主要动作是“复制”，指导的主要内容是可执行建议；诊断信息折叠。
- 语境区域展示本次实际使用的聊天或用户补充内容，帮助销售判断建议是否接题。

### 客户资料

- 用头像、昵称／备注、工作号帮助销售确认对象。
- 画像先呈现与销售行动有关的摘要，详细依据按需展开。
- 长客户 ID、内部来源字段和技术状态放到诊断详情；准确的对象校验由程序承担。

### 销售物料

- 每个面板一个主标题，去掉“销售助手→团队物料→团队物料”的重复层级。
- 卡片突出标题、预览和复制／分享；删除、上传等管理操作放到更多菜单或编辑区域。
- 保留点击标题编辑，并加轻量编辑提示；保留图片点击放大。
- 新增入口清楚区分图片、文字和链接，选图时主动收起浮窗。
- 个人标题、团队标题和别名规则由流程处理，销售只需理解“按自己的名称保存”。

### 跟进与设置

- 跟进页将待查看、全部活跃、忽略列表做成稳定的视图切换；刷新作为独立操作。
- 设置先展示日常开关，其次当前工作号，最后是折叠的管理与诊断区。
- 悬浮位置采用拖动并记忆位置，去掉裸露的 Y 轴数字滑杆。
- 工作号仍在设置中统一管理，缺少工作号的页面提供直达入口，选定后回到原任务。

## 四、补齐状态反馈：每个状态都有下一步

| 状态 | 展示与操作 |
| --- | --- |
| 首次使用／缺少工作号 | 简短说明＋选择工作号入口，完成后接回原任务 |
| 列表加载中 | 列表骨架或轻量加载反馈；已有缓存继续展示 |
| 生成中 | 显示当前进度及等待反馈，保留输入与已有结果 |
| 请求失败 | 显示失败原因与重试入口，保留已有内容 |
| 物料库确实为空 | 说明可以添加什么，并提供新增入口 |
| 搜索无结果 | 保留关键词，提供清除筛选或调整搜索入口 |

团队物料请求失败时只显示失败状态，修正同时出现“暂无物料”的问题。错误文案使用销售能理解的语言，详细异常留在诊断区。

## 五、统一视觉：建立一个有完成度的产品界面

- 第一版视觉稿采用品牌红作为少量主要操作的强调色，正文与容器使用中性配色；错误状态另有清晰的文字和图标表达。
- 统一标题、正文、辅助信息的字号与间距，减少同一屏幕上抢眼的蓝色文字按钮。
- 图标与文字共同表达功能，未就绪的入口仍清楚可辨，并能引导用户补齐条件。
- 全部容器使用统一主题颜色，覆盖深浅模式，修正白色悬浮条和固定浅灰背景。
- 关闭等图标保留至少 48dp 触控区域，视觉图形可以更小。
- 视觉方案阶段结合 Taste Skill，围绕同一任务布局完善配色、密度和细节。

## 执行顺序与验收

1. **先做交互原型。** 落实面板形态、工具条和三个典型任务：客户→画像／指导／回复；物料→预览→复制／分享；跟进→复制姓名→返回微信。使用高考美术培训的家长与学生场景。
2. **再实现结构改版。** 容器、导航、内容保留、结果布局和状态反馈一起完成，保持现有业务接口与个人／团队物料关系。
3. **最后统一视觉并在工作机上走完整任务。** 检查正常尺寸、小屏大字体、键盘开启、面板切换、长内容和请求失败。

验收看实际操作：入口是否看得懂，聊天与助手能否顺畅往返，草稿是否保留，图片能否放大和复制，跟进姓名能否复制，错误后能否继续。通过同一组任务的改版前后对照判断改善。

## 实施备注

- 本地物料已有确认删除步骤，改版保留；本次改的是动作层级。

- 原型中的聊天语境接现有可用数据，训练数据采集另行处理。
