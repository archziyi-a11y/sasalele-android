## 本轮范围

本轮实现用户确认的第一阶段：个人改名保存到本机、其他工作号能搜索并采用别名、记录三类命名依据。**没有自动替换团队公共标题，也没有手动投票、模型评分或员工个人账号体系。**

v28 的公共改名 HTTP 接口现在返回 `material_public_rename_disabled`，不能继续直接修改团队标题。此前已经修改过的公共标题保持服务器当前值，不自动追溯恢复。

## 员工操作

1. 在「团队物料」点击「保存到本机 / 自定义标题」，填写个人标题并保存。
2. 同一团队素材已在本机时，入口显示「修改本机标题」，更新同一条记录，保留收藏，不重复创建。
3. 团队标题保持原样；个人填写的非默认名称成为团队可搜索别名。其他工作机刷新团队库后能搜索到。
4. 搜索结果仍是一条素材卡片，同时显示匹配名称。只有一个别名匹配且公共标题未匹配时，会选中该匹配名称；多个别名同时匹配时，须点选具体名称，系统不擅自归因。
5. 沿用选中的名称保存到本机，记作采用候选；修改输入框里的名称，记作主动命名。复制／分享仍使用素材正文或图片文件，不复制别名当正文。
6. 个人标题不随团队库刷新改变。收藏仍只在本机保存。公共删除仍由管理员执行。

普通的本机图片或文本仍可直接改名，但只有具备团队来源关系的素材，才会把个人改名作为该团队素材的候选。

## 关联与旧素材

客户端 Room 数据库从4迁移至5，新增来源、别名及命名来源字段，并新增命名待发送表。旧素材、收藏、提醒等原有数据保留。

- 新保存的团队副本使用「服务地址摘要＋团队素材ID」唯一关联。手机上多次保存不会增加副本。
- 以后从本机上传团队时，利用上传回执建立关联；上传时填写的团队标题不会覆盖原本机标题。
- v27／v28 的旧素材没有来源ID，不能仅凭同名认定为同一条。保存时如发现内容完全相同的未关联旧记录，会提供「关联已有」选项；图片通过文件摘要核对。员工明确选择后才更新该条旧记录，否则创建独立本机副本。
- 团队图片保存到本机时复制到持久素材目录，下载缓存回收不删除本机副本。
- 同一台工作机切换工作号不会自动切换或清空本机库；行为归属使用操作发生时选定的工作号。

## 三类依据与统计口径

| 依据 | 触发 | 后台字段 |
| --- | --- | --- |
| 主动命名，高置信候选 | 输入非默认标题并保存 | explicit_accounts：当前主动支持该别名的不同工作号数 |
| 搜索后使用，中等置信候选 | 搜索明确命中／选中别名后复制或分享 | search_use_accounts：有此类记录的不同工作号数，排除曾主动提出该别名的工作号 |
| 沿用候选保存，高置信候选 | 选择别名并保持名称不变，保存到本机 | adopt_accounts：当前采用该别名的不同工作号数 |

`unique_accounts` 是当前明确支持者与合格搜索使用者的并集人数，不能把上面三列简单相加。统计单位是工作号，不是已验证的员工自然人。

- 同一工作号、多设备支持同一素材，只保留一个当前明确支持。改成另一候选时转移；保存公共默认标题时撤销对候选的当前明确支持。
- 当前明确支持以服务器最近接收的有效保存为准；跨设备离线补传时，不把接收先后当作真实操作先后。
- 同一工作号的复制或分享，按素材、别名、行为类型和**服务器UTC接收日期**去重。报告再按工作号合并，所以复制后分享不会增加独立人数。
- 直接沿用公共默认标题不创建独立候选。反复保存、确认未变化的本机标题不应变成新的独立提出者；再次沿用此前采用的别名保留采用来源。
- 候选只合并首尾／连续空白差异，不做模型语义合并。
- 本轮报告中的明确支持是当前状态，搜索使用是历史记录；没有据此自动算分或自动晋升。后续设定时间窗口、衰减与晋升门槛时，应使用原始接收记录进一步计算。

## 离线与授权

本机副本和命名依据在同一 SQLite 事务中保存。断网不会要求重新导入图片；命名依据留在本机待发送表，刷新团队库时补传。操作时工作号固定写入记录，切换工作号不会把旧操作转记给新号。

命名上传使用既有工作机授权和工作号授权校验。待发送时通过普通工作号接口更新账号范围缓存，不拉取聊天，不调用模型。素材内容仍在独立团队库，不依赖飞书。未选择工作号时允许本机保存，并明确提示本次不计入标题统计，之后不会擅自归给新选的工作号。

已下架素材、失效候选等永久失败移入失败记录，不会一直阻塞后续有效命名。界面刷新会提示；最近100条失败记录保留在本机。临时网络、账号缓存或授权问题保留待发送，恢复后重试。

不保存搜索原文、微信收件人或聊天内容。记录素材ID、别名ID、工作号、行为类型、命名来源和服务器接收时间。不能把服务端接收时间当成真实操作发生时间，尤其是离线补传时；本轮没有据此计算消息延迟。
