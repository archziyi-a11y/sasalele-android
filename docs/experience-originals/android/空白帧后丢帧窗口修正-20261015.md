# 空白帧后丢帧窗口修正 v8

## 用户日志的事实

工作机PKW110/Android15/v7同一请求：授权成功、目标交接成功、收到画面并检测空白；检测空白后3024ms结束。日志只显式记录一个空白帧，不能证明连续收到很多全黑帧；也不能证明截图文件存储失败、OCR失败或微信必然限制。

ADB仅检查微信窗口标记元数据：当前有surface的微信窗口未显示标准SECURE标记；没有读取标题、像素或聊天。此观测不等于排除其他OEM隐私机制，亦不是捕获时刻的完整窗口历史。官方FLAG_SECURE含义参考https://developer.android.com/security/fraud-prevention/activities 。

## 已发现的代码缺陷

我在v6空白帧等待逻辑中加入readyAfter=当前时间+100ms，随后回调会丢弃该时间之前到达的帧。这会丢掉短暂空白后紧接着的有效帧；静态画面可能之后不再产生更新。该路径缺陷由代码证实，但用户原日志没有帧计数，因此它是否为本次真机根因仍是待验证解释。

v8去掉这段丢帧窗口；在同一系统授权/虚拟显示内接受下一有效帧。保留约3秒空白等待上限、15秒整体上限和结束后释放资源。新增收到帧总数、空白帧数元数据；超时改为“未获得有效画面（收到N帧，空白M帧）”，不把单帧后无更新误称持续返回空白。持久诊断继续保留，不新增图片/聊天/凭据日志。
