# 空白首帧与截图保存错误排查

## 已确认与未确认

用户提供的最近状态为“画面受保护或截图处理失败”。该文案来自v5截图服务的图片后处理catch：此时已收到ImageReader画面、转换Bitmap并释放MediaProjection，之后可能在纯黑检查、目录建立、PNG压缩或文件写入失败。它不能证明微信FLAG_SECURE或其他保护机制，也不能据此归因于业务网络/OCR。

旧实现先释放投屏，再检查第一帧是否为全黑；纯黑抛异常，与存储/编码错误合并提示。真机未连接ADB，未取得异常堆栈，未确认具体分支；未自动操作微信或提取附件聊天正文。

## 本轮实施

- 一次MediaProjection授权内保留首帧检查；检测到空白时丢弃该帧并回收Bitmap，短暂等待后续正常帧，不重新授权/创建虚拟显示。
- 从首个空白帧起最多等待约3秒；即便没有后续回调也有定时退出。整体截图仍有原15秒超时。连续空白明确提示“无法确认是否受保护”，结束会话、恢复浮窗，提供系统截屏后选图入口。
- PNG编码与本地文件保存分别反馈；其他后处理失败保留阶段和异常类型，不显示客户信息或授权数据。
- 退出服务时清理定时回调；每个服务请求有独立空白计时，避免上次超时污染下一次。
- 没有添加绕过受保护窗口机制，不持续录屏，不写公共相册，不上传图片。维持逐次授权，未实施此前讨论的长期共享会话。

原生产Kotlin编译类在主机Java运行3项合成时序验证：空白后有效帧可接受；连续空白/无后续帧到界限停止；新请求不继承旧计时。证据private/capture-investigation/v6-frame-gate-tests.txt。新增CaptureFrameGateTest.kt供后续instrumentation使用，但本轮没有运行该Android测试类，不把主机测试写成Android测试通过。

模拟器AVD Zibai_Pixel_API_36、serial emulator-5554、API36。独立包名同配置release测试包完成授权取消及新授权允许；图片预览为本地模拟页、无助手覆盖、中文OCR读到测试客户甲；截图服务已释放。证据private/capture-investigation/v6-cancelled.png、v6-captured.png、v6-capture-checks.json。未复现真机微信特有的空白帧，也未验证设备是否限制第三方投屏。
