# SASALELE 现有 UI 评审（缺点与漏洞）

评审日期：2026-10-15（v2，含自我更正）
评审方式：安装 release 包到专用模拟器 emulator-5554（1080×2400 / 420dpi / API 36），逐面板点按 + 源码核对
评审范围：MainActivity 主界面、悬浮工具条、7 个业务面板、主题与配色、深色模式、触摸行为

---

## 零、对 v1 的更正

v1 里我把「展开工具条后点击桌面 Gmail，Gmail 没打开、浮窗反而收起」当成 P0 漏洞，这是**错的**：

1. 那次测试只做了一次，且我误判了面板位置——随后用来验证「点不掉面板」的坐标 (200, 1500) 其实落在**白色面板内部**，不是在面板外。用一个落在面板里的点去论证「点面板外没反应」，结论无效。
2. 本轮重测：面板打开时点击面板上方空白区 (540, 300) → **面板正常收起**。设计意图实际是生效的。
3. 我测到的「Gmail 没打开」是**这个设计的必然结果**，不是 bug：浮层吃掉这一击、并把它解释为「用户想收起」。这正是「点击外部关闭」的标准语义（Compose 的 Popup / Dialog 的 outside dismiss 同样不回传触摸）。

**结论：「点击外部收起」这个设计本身没有问题，是常规做法。** 下面的问题清单已据此重写。

## 一、结论摘要

现有 UI 属于「功能跑通了、界面还没做」的状态：结构可用，但**品牌为零、信息层级为零、深色模式为零**，文案与信息架构也还没按一线销售的使用场景收拾过。

| 级别 | 问题 | 影响 |
|---|---|---|
| P1 | 6 个入口图标语义错位 5 个（提醒=红心、素材=扳手、指导=星星、客户=通用人形），且默认无文字标签 | 新用户无法一眼找到功能，只能逐个试 |
| P1 | 完全无深色模式（大量硬编码 `Color.White`） | 深色手机/夜间场景白块刺眼，与聊天界面割裂 |
| P2 | 品牌色走系统动态取色，颜色由用户壁纸决定 | 同一 App 在不同手机上颜色不同，品牌识别为零 |
| P2 | 面板 280×400dp 定死，实测约 80% 面积是空白 | 小屏溢出、大屏空洞，信息密度极低 |
| P2 | 面板标题与入口名不一致；两个面板首行高度雷同 | 用户怀疑自己点错 |
| P2 | 3 个面板声明了 `onClose` 却从未调用，面板上没有任何关闭入口 | 只能靠「点空白」关闭，可发现性差 |
| P2 | 面板外做**滑动手势**时，既不收起也不下沉，完全无响应 | 手感像卡死（建议：外部滑动也收起） |
| P3 | 全部文案硬编码在 Kotlin，颜色/字号硬编码 | 无法本地化、无法统一改版 |
| P3 | 联调假数据（picsum 狗图）混进产品 UI；源码目录残留 `_append.txt` | 交付观感与代码卫生 |

## 二、点击外部收起：设计没问题，但有两处手感缺口

### 实测结论（已复现）

| 操作 | 结果 |
|---|---|
| 面板打开，点面板上方空白 (540, 300) | 面板收起 ✅ 符合设计 |
| 工具条展开，点桌面任意处 | 工具条收回 ✅ 符合设计 |
| 面板打开，在面板外做上滑手势 | **无任何反应**（不收起、下方也不滚动） |
| 面板打开，点面板内部空白 | 无反应，面板保留 ✅ 正确 |

### 建议补两点

1. **外部滑动手势也应该收起面板**。现在是「点了不动」——手势被吞掉但没有任何反馈，用户会以为卡死。走同样的 `contentBounds` 判断加一个 `detectDragGestures` 即可，成本很低。
2. **`isExpanded` 初始值是 `true`**（`FloatingWindowContent.kt:82`），即服务一启动工具条就是展开态、窗口即为全屏。这意味着用户开启助手后的**第一次点击会被当成「收起」吃掉**。如果希望首屏是「安静地贴在边上」，改初始值为 `false` 更符合直觉——这取决于你想要哪种开场，由你定。

### 需要你确认的一个产品判断

工具条/面板打开期间整屏被浮层占用，**用户无法滚动或查看底层的聊天记录**。如果定位是「面板是弹性的、看完就关」，这没问题；如果定位是「一边看指导一边翻聊天记录」，那用户就得反复「关面板 → 翻记录 → 再打开」，这个来回值得再权衡。

## 三、P2：三个面板声明了 `onClose` 却从未调用

```kotlin
fun MaterialsPanel(context: Context, onClose: () -> Unit) { ... }   // onClose 在函数体内一次都没出现
fun SettingsPanel(context: Context, onClose: () -> Unit) { ... }    // 同上
fun RemindersPanel(onClose: () -> Unit) { ... }                     // 同上
```

三个面板的 header 都长这样，`SpaceBetween` 下只剩一个孤零零的标题：

```kotlin
Row(horizontalArrangement = Arrangement.SpaceBetween) {
    Text("销售物料", fontWeight = FontWeight.Bold, fontSize = 18.sp)
    // ← 这里原本应该有关闭按钮
}
```

说明代码里本来设计过关闭按钮，后来被删了、参数留下来没人用。配合「点空白关闭」，可发现性不足——用户不一定知道能点空白。

**建议**：要么把 `onClose` 接上一个显式的关闭图标（推荐，外部点击收起可以同时保留），要么把死参数删掉、让代码诚实。

## 四、P1：图标语义全错位

| 入口 | 实际图标 | 用户会读成 |
|---|---|---|
| 客户资料 | `AccountCircle`（通用人形） | 我的账号 / 个人中心 |
| 销售指导 | `Star`（星星） | 收藏 / 评分 |
| 帮你回 | `ChatBubble` | 消息 / 聊天记录 |
| 待处理提醒 | `Favorite`（红心） | 收藏 / 点赞 |
| 常用素材 | `Build`（扳手） | 工具 / 设置 / 维修 |
| 设置 | `Settings`（齿轮） | 设置 ✅（唯一正确的） |

6 个图标里 5 个语义错位，且**默认不显示文字标签**（`label` 只有绑定客户后才显示客户名）。项目自己的验收记录也写过「头像仍是通用人形，素材为扳手图标」，说明被指出过但没修。

## 五、P2：命名与文案

### 1. 面板标题和入口名对不上

| 点哪个入口 | 实际看到的首行 |
|---|---|
| 常用素材 | 「销售物料」 |
| 帮你回 | 「未绑定客户 · 真实业务草稿」 |
| 销售指导 | 「真实业务上下文 · 未绑定」 |
| 待处理提醒 | 「智能跟进提醒」 |

后两条尤其容易混：「真实业务草稿」和「真实业务上下文」首行结构几乎一样，用户很难分辨自己在哪个面板。（v1 里我说这两个是同一个面板，那是被误触的坐标骗了——它们是两块不同的代码，但**呈现上确实过于雷同**。）

### 2. 术语直接甩给一线销售

面板里出现大量内部术语：「按双标识取得近期聊天与历史画像」「画像作业写入 / 摘要生成时间未知」「上下文预算：{...}；真实模型未接入」「别名索引：x 条；完整性 数量对齐（非实时快照）」「degraded」。销售看不懂就等于没有信息。

### 3. 设置面板把内部工具暴露给销售

平铺三个 TextButton：「检查服务／重试」「管理员发机配置」「开发诊断（非日常使用）」。其中两个是管理员/开发用途。而销售真正常用的「生成后自动复制」「开启跟进提醒」被挤在下面。另外「悬浮窗默认 Y 轴位置: 328」配一个 0..1000 的裸 Slider，用户无法理解这个数字。

## 六、视觉与规范

1. **深色模式完全没做**：`Color.White` / `Color(0xFFF0F0F0)` / `Color(0xFFF5F5F5)` / `Color.Red` / `Color.LightGray` 大量硬编码；实测切深色后浮窗仍是纯白。
2. **品牌色被系统动态取色接管**：`Theme.kt` 里 `dynamicColor = true`，`Color.kt` 还停在 Android Studio 模板的 `Purple40 = 0xFF6650a4`。结果主色由用户壁纸决定。项目已有品牌资产 `design/icons/sasalele-icon-white-red-v2.png`（白红），但 UI 里完全没体现。
3. **字号没有体系**：`Type.kt` 只覆写了 `bodyLarge`，面板里散落内联 `18.sp` / `16.sp` / `14.sp` / `9.sp`，9sp 标签在 420dpi 上几乎不可读。
4. **面板尺寸定死** `280.dp × 400.dp`，不响应屏幕宽度、字号缩放、横屏。
5. **空状态简陋**：提醒面板只有一个居中灰字「暂无待处理提醒」；未绑定态点「销售指导」只弹 Toast「请先识别客户」，按钮不变灰、不给下一步。
6. **联调假数据混进产品 UI**：`MaterialsPanel` 里 `LaunchedEffect` 播种了一条 `https://fastly.picsum.photos/id/237/...`（一张狗图）当作示例素材。
7. **测试脚手架文件残留在源码目录**：`app/src/main/java/com/example/sasalele/FloatingWindowContent_append.txt`。
8. **对比度不足**：未绑定态图标用 `Color.LightGray` on 白底，约 1.6:1，远低于图标所需的 3:1。
9. **破坏性操作无二次确认**：「解除绑定」是整宽红色 Button，一点即解绑。
10. **主界面（MainActivity）几乎没设计**：两个大按钮平铺顶部、默认 TabRow、列表项无头像/无时间/无未读；而它本质是测试脚手架（文案是「模拟消息摘要…」「这是本地模拟消息，不应被顶栏OCR提取」），却看起来像正式功能入口。

---

## 七、下一步建议（优先级）

1. **修图标语义 + 加短标签**，把 6 个入口收敛到 5 个以内
2. **建品牌色板与字号阶梯**，关掉动态取色，把白红品牌资产落进 UI；同步补深色模式
3. **重做面板骨架**：统一 header（标题 + 关闭按钮，顺手把 `onClose` 接上）、统一卡片/列表项、统一空状态
4. **补外部滑动收起**，消掉「手势无响应」的手感缺口
5. **重写文案**：面向一线销售，去掉内部术语
6. 清掉假数据与残留文件
