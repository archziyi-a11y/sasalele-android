# 真实图片识别接入

2026-10-12，北京时间。已实现真实端侧中文OCR，未实现屏幕截图获取，也未接入实时方舟或模型。

## 方案

采用随包中文ML Kit 16.0.1，模型无需首次通过Play服务下载。先对选择图片的顶部18%进行OCR，识别耗时来自elapsedRealtime，从图片解码前至识别结果处理后，不代表网络或消息同步耗时。顶栏规则只排除可观察的群人数、公众号或列表标志，不能证明所有私聊分类准确，因此用户确认图片是一对一私聊后才搜索身份。

识别文字可核对、修正。匹配用工作账号限定及规范化后名称/别名相等；不按部分姓名自动猜测，不自动绑定，重名全部展示供选择。

复用旧探针已授权的customer-identity-sample.json，只保存于private/bundled-assets并加入Git忽略。Gradle打包该目录。源码仓库不包含真实样本，但APK含身份样本。无样本时明确提示不能匹配，摘要为空显示暂无摘要，不生成虚构画像。

## 验证

- assembleDebug成功。
- HeaderIdentityRulesTest：6项本地规则测试通过，包含群聊、列表、公众号排除及精确别名、不匹配部分姓名。
- RealOcrTest：3项设备测试通过，包含真实中文顶栏识别、不识别位于正文区域的测试文字、真实群人数识别排除和匹配账号隔离/多候选/无匹配。
- 设备实际是Zibai_Pixel_API_36，Android16，serial emulator-5554。测试前未重新核对AVD名称，执行中发现与旧专用模拟器不同后已记录；没有操作微信、没有清除应用数据，临时合成图片测试后删除。
- 新APK已安装；本轮未验证销售人员真实微信截图识别准确率及完整手工选图→绑定体验。

## 限制与下一步

长按仍打开已有图片选择器，不是截当前屏幕。图片预览与顶部文字只在当前面板内存处理，不上传图片。OCR准确率、标题位置、昵称省略、多行顶栏、昵称含括号人数导致误排除仍需真实样本验证；用户修改姓名不是新的身份验证。

下一步用实际私聊截图核对顶栏和匹配，再实现MediaProjection截图授权、浮窗隐藏和取消恢复。保留手动核对和无匹配反馈，不宣称OCR即客户身份验证成功。
